বাস্তব প্রজেক্টে নগদ গেটওয়ে ইন্টিগ্রেশন করতে গিয়ে যে যে সাধারণ সমস্যাগুলো হয়, সেগুলোর দ্রুত সমাধান এবং প্রোডাকশন লেভেলের সিকিউরিটি স্ট্যান্ডার্ড।

Common Real-World Errors & How to Fix

1. Failed to verify signature (`16_0006_058`) 16_0006_058

কারণ: সিগনেচার অ্যালগরিদম হিসেবে OPENSSL_ALGO_SHA1 ব্যবহার করা হয়েছে অথবা নগদ পোর্টালে আপলোড করা পাবলিক কী এর সাথে আপনার প্রাইভেট কী মেলেনি।

সমাধান: openssl_sign ও openssl_verify উভয়ে OPENSSL_ALGO_SHA256 ব্যবহার করুন এবং পোর্টালে আপনার সঠিক পাবলিক কী আপলোড নিশ্চিত করুন।
2. Duplicate Order ID in same day (`16_0006_083`) 16_0006_083

কারণ: টেস্ট করার সময় একই হার্ডকোডেড Order ID (যেমন 123456) বারবার ব্যবহার করা হয়েছে। নগদে একই দিনে একই Order ID দ্বিতীয়বার পাঠানো যায় না।

সমাধান: প্রতিবার ডায়নামিক ও ইউনিক Order ID জেনারেট করুন (e.g. 'ORD' . date('YmdHis') . rand(100, 999))।
3. Invalid Sensitive Data (`16_0006_059`) 16_0006_059

কারণ: sensitiveData অবজেক্টের কী (Key) নেমে ভুল ছিল (যেমন dateTime দেওয়া হয়েছিল ছোট হাতের datetime না দিয়ে)।

সমাধান: sensitiveData-তে অবশ্যই 'datetime' => $dateTime (ছোট হাতের t) ব্যবহার করুন।

Local Development vs. Live Production

Local Development (127.0.0.1)

  • Initialize ও Complete API কল সফলভাবে লোকালহোস্ট থেকেই টেস্ট করা যায়।
  • কিন্তু কাস্টমার পেমেন্ট সম্পন্ন করার পর নগদ আপনার লোকালহোস্ট দেখতে পাবে না।
  • সমাধান: লোকাল টেস্টের জন্য Ngrok বা Cloudflare Tunnel ব্যবহার করে পাবলিক URL বানিয়ে NAGAD_CALLBACK_URL-এ দিন।

Live Production

  • অবশ্যই ভ্যালিড SSL সহ HTTPS ডোমেন ব্যবহার করতে হবে (e.g. https://yourdomain.com/api/nagad/callback)।
  • আপনার লাইভ সার্ভারের স্ট্যাটিক পাবলিক IP নগদ মার্চেন্ট পোর্টালে হোয়াইটলিস্ট করে নিতে হবে এবং X-KM-IP-V4 হেডারে পাঠাতে হবে।

Production Security Checklist

Never Commit Private Keys

.pem ফাইল এবং .env কখনো গিটহাবে পুশ করবেন না। .gitignore-এ অ্যাড রাখুন।

Never Trust Callback Blindly

কলব্যাক পাওয়ার পর সবসময় Verify Payment API কল করে স্ট্যাটাস চেক করুন।

Match Amount & Order ID

Verify রেসপন্সের Amount এবং Order ID আপনার ডাটাবেজের সাথে হুবহু মিলতে হবে।

Handle Idempotency

একই অর্ডারের জন্য বারবার কলব্যাক এলেও যাতে ডাবল প্রসেস বা প্রোডাক্ট ২ বার একটিভ না হয়।

Recommended Database Schema

Column Name Type Description
order_id VARCHAR(50) UNIQUE আপনার সিস্টেমের ইউনিক অর্ডার নম্বর।
payment_ref_id TEXT NULLABLE নগদ কর্তৃক প্রদত্ত paymentReferenceId।
amount DECIMAL(10,2) পেমেন্টের টাকার পরিমাণ।
status ENUM('pending', 'paid', 'failed') বর্তমান পেমেন্ট স্ট্যাটাস।
issuer_ref_no VARCHAR(100) NULLABLE নগদ ট্রানজ্যাকশন আইডি (TrxID)।

Frequently Asked Questions (FAQ)

নগদ পেমেন্ট গেটওয়ের জন্য কি কোনো অফিসিয়াল SDK আছে?

নগদ সরাসরি কোনো অফিসিয়াল ফ্রেমওয়ার্ক SDK মেইনটেইন করে না। তারা শুধুমাত্র REST API ডকুমেন্টেশন এবং কী-পেয়ার প্রদান করে। তাই নিজস্ব সার্ভিসে নেটিভ HTTP Client ও OpenSSL দিয়ে ইন্টিগ্রেট করাই সবচেয়ে দ্রুত ও নির্ভরযোগ্য উপায়।

আমার সার্ভারের টাইমজোন কি এশিয়া/ঢাকা (Asia/Dhaka) হতে হবে?

হ্যাঁ। নগদের API রিকোয়েস্টের dateTime ফরম্যাট YmdHis (e.g. 20260929112358) আশা করে বাংলাদেশ স্থানীয় সময়ে। তাই টাইমস্ট্যাম্প জেনারেট করার সময় now('Asia/Dhaka') নিশ্চিত করুন।

Nagad Online Payment Gateway Integration Guide

যেকোনো প্রোগ্রামিং ল্যাঙ্গুয়েজ (PHP, Node.js, Python, Go, Java ইত্যাদি)-এ কোনো থার্ড-পার্টি প্যাকেজ ছাড়াই নগদের সরাসরি REST API, RSA পাবলিক-প্রাইভেট কী এনক্রিপশন এবং SHA256 ডিজিটাল সিগনেচার দিয়ে পেমেন্ট গেটওয়ে ইন্টিগ্রেশন করার সহজ ও প্রফেশনাল হ্যান্ডবুক।

1 Introduction & Background

বাংলাদেশ ডিজিটাল ফিনান্সিয়াল সার্ভিস (DFS)-এর অন্যতম জনপ্রিয় গেটওয়ে হলো নগদ (Nagad)। সাধারণ থার্ড-পার্টি প্লাগিন ছাড়া কীভাবে নগদের সরাসরি API কল করতে হয় এবং এর পেছনের ক্রিপ্টোগ্রাফিক সিকিউরিটি (RSA Encryption + SHA256withRSA Signature) কীভাবে কাজ করে তা একজন নতুন ডেভেলপারের জন্য বোঝা অত্যন্ত জরুরি।

এই ডকুমেন্টেশনের বিশেষত্ব: আপনি যেকোনো প্রোগ্রামিং ফ্রেমওয়ার্ক ব্যবহার করুন না কেন—কনসেপ্ট, ক্রিপ্টোগ্রাফি, এপিআই কল এবং ডাটা ফ্লো সব জায়গায় একই। এই গাইডটি পড়ার পর আপনি কোনো প্যাকেজ ছাড়াই সম্পূর্ণ নিজের কোডে নগদের পুরো পেমেন্ট লাইফসাইকেল ডেভেলপ করতে পারবেন।

2 Payment Gateway Mental Model

পেমেন্ট গেটওয়ে কীভাবে কাজ করে? ধরুন একজন কাস্টমার আপনার ওয়েবসাইটে ১,০০০ টাকার একটি প্রডাক্ট কিনবেন। আপনার সার্ভার কখনোই কাস্টমারের নগদ পিন (PIN) বা ওটিপি (OTP) সরাসরি নেয় না।

3 Full Payment Lifecycle (Step-by-Step)

1

Initialize Phase

পেমেন্ট সেশন শুরু করে। নগদ সার্ভার থেকে একটি paymentReferenceId এবং সিকিউরিটি challenge সংগ্রহ করা হয়।

2

Complete / Place Order

টাকার পরিমাণ ও কলব্যাক URL পাঠিয়ে নগদ পেমেন্ট পেজের লিংক (callBackUrl) তৈরি করা হয় এবং কাস্টমারকে সেখানে পাঠানো হয়।

3

Callback & Verify

কাস্টমার পেমেন্ট সম্পন্ন করার পর সার্ভার-টু-সার্ভার Verify Payment API কল করে ট্রানজ্যাকশন স্ট্যাটাস Success নিশ্চিত করে অর্ডার PAID করা হয়।

4 Integration Credentials

নগদ মার্চেন্ট পোর্টাল থেকে লাইভ বা স্যান্ডবক্স ইন্টিগ্রেশনের জন্য নিচের ক্রেডেনশিয়ালগুলো সংগ্রহ করতে হবে:

Credential Key Description Example Placeholder
NAGAD_BASE_URL নগদ এপিআই-এর মেইন বেস ইউআরএল। https://api.mynagad.com/api/dfs
NAGAD_MERCHANT_ID আপনার জন্য বরাদ্দকৃত ইউনিক মার্চেন্ট আইডি। YOUR_MERCHANT_ID
NAGAD_ACCOUNT_NUMBER মার্চেন্ট ওয়ালেট বা নগদ অ্যাকাউন্ট নাম্বার। 017XXXXXXXX
NAGAD_CALLBACK_URL পেমেন্ট শেষে কাস্টমার যেখানে রিডাইরেক্ট হবে। https://yourdomain.com/api/nagad/callback
NAGAD_API_VERSION এপিআই ভার্সন হেডার। v-0.2.0
NAGAD_CLIENT_TYPE ক্লায়েন্ট টাইপ হেডার। PC_WEB

5 কী জেনারেশন, ডাউনলোড ও ফাইল ম্যানেজমেন্ট গাইড

কোন কী কিভাবে তৈরি করবেন, কোথায় আপলোড করবেন এবং কোন কী-টি আপনার কোডের কোথায় রাখবেন তা নিচে বিস্তারিত দেখানো হলো:

A ১ম ধাপ: আপনার নিজের RSA Key Pair জেনারেট করুন

টার্মিনালে ওপেনএসএসএল (OpenSSL) কমান্ড রান করে আপনার নিজস্ব ২০৪৮-বিট RSA কী-পেয়ার তৈরি করুন: 

# ১. আপনার Merchant Private Key তৈরি করুন
openssl genrsa -out nagad_private_key.pem 2048

# ২. প্রাইভেট কী থেকে Merchant Public Key বের করুন
openssl rsa -in nagad_private_key.pem -pubout -out nagad_merchant_public_key.pem
B ২য় ধাপ: নাগাদ মার্চেন্ট পোর্টালে আপলোড ও নাগাদ পাবলিক কী ডাউনলোড
  • নগদ মার্চেন্ট পোর্টালে লগইন করে Merchant Integration মেন্যুতে যান।
  • আপনার জেনারেট করা nagad_merchant_public_key.pem ফাইলের কনটেন্ট সেখানে আপলোড/পেস্ট করুন।
  • পোর্টাল থেকে নগদের নিজস্ব Nagad Gateway Public Key টি কপি/ডাউনলোড করুন এবং সেভ করুন nagad_public_key.pem নামে।
C ৩য় ধাপ: আপনার প্রজেক্টের স্টোরেজে ফাইলগুলো রাখুন 
storage/keys/nagad/
├── nagad_private_key.pem  # <-- আপনার নিজস্ব Merchant Private Key
└── nagad_public_key.pem   # <-- পোর্টাল থেকে ডাউনলোড করা Nagad Gateway Public Key

6 The 3 Cryptographic Keys (কে কোন কাজে লাগে)

1. Merchant Private Key

আপনার নিজের সিক্রেট কী।
আউটবাউন্ড রিকোয়েস্টে ডিজিটাল সিগনেচার তৈরি করতে এবং নগদ থেকে আসা রেসপন্স ডিক্রিপ্ট করতে ব্যবহৃত হয়।

Keep strictly secret

2. Merchant Public Key

আপনার পাবলিক কী।
এটি নগদ পোর্টালে আপলোড করা থাকে। নগদ এই কী দিয়ে আপনার রিকোয়েস্টের সিগনেচার ভ্যালিডেট করে।

Uploaded to Nagad

3. Nagad Gateway Public Key

নগদ কর্তৃক প্রদত্ত পাবলিক কী।
নগদ সার্ভারে ডেটা পাঠানোর আগে এনক্রিপ্ট করার জন্য এবং নগদ থেকে আসা রেসপন্সের সিগনেচার ভেরিফাই করার জন্য এটি লাগে।

Provided by Nagad

7 Encryption vs. Digital Signature: স্পষ্ট পার্থক্য

ENCRYPTION (ডেটা গোপন রাখা)

সেন্সিটিভ ডেটা যাতে নেটওয়ার্কে কেউ দেখতে না পারে, সেজন্য নগদ গেটওয়ে পাবলিক কী দিয়ে ডেটা লক (Encrypt) করা হয়। একমাত্র নগদ ছাড়া কেউ তা খুলতে পারবে না।

Plain JSON → RSA Encrypt (PKCS1 Padding) → Base64 Encode
SIGNATURE (সত্যতা ও অখণ্ডতা নিশ্চিত করা)

রিকোয়েস্টটি আসলেই আপনার সার্ভার থেকেই এসেছে এবং কোনো ডেটা ম্যানিপুলেট করা হয়নি, তা নিশ্চিত করার জন্য আপনার মার্চেন্ট প্রাইভেট কী দিয়ে সিগনেচার তৈরি করা হয়।

Plain JSON → SHA256withRSA Sign → Base64 Encode
